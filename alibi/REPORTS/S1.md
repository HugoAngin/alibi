## How it was checked

For each module, one agent built it, two independent reviewers (correctness and adversarial)
tried to break it, and a fixer repaired every confirmed finding and added a regression test.
Every review found real defects. Examples that are now fixed:

- **Store:** a self-supplied import could take an issuer's `record_id` first. Self-supplied ids
  now carry a `self_` prefix. Rows edited without the key were served silently; they are now
  integrity-checked.
- **Package:** a substring scrub broke honest packages (`ord_100` matched inside `ord_1001`). A
  duplicate attachment let an unsigned copy override the signed one.
- **Ingest and gateway:** one bank connection could rewrite another connection's transactions.
  RFCs naming `txn_ids` were not bound to the bank's own accounts. Settlement lookups were not
  bound to the issuer.
- **Investigation:** a self-supplied payout or settlement could produce `supported`. A
  conflicting settlement already in the passport was ignored. A failed payout was not
  `contradicted`.
- **API:** re-running the flow crashed at `approve`. `record_policy` could leave a less
  restrictive policy in force. `verify_package` could create keys and overwrite the trust
  registry.
- **Lead fix (26e705a):** the rules engine sums a one-kind total with +1, but the package checked
  netting signs. So Bank B's refunds total (18000) arrived `unresolved`. Now one rule applies:
  - `net_payout` and `net_total` use `SIGN_BY_KIND`.
  - Any other total covers one kind with one sign.
- **Per-bank request ids (8804ec3 and the next commit):** request ids were global, so a bank that
  sent another bank's id first blocked the genuine request and learned the id existed. A request
  is now `(audience, request_id)` end to end:
  - store key and lookups, ingest, claims, run ids, `case_ref`, review and dispatch;
  - the public API resolves a bare id only while one bank alone has used it (S5 merge: teammates'
    acceptance tests and the app call bare ids); a shared bare id raises `AmbiguousRequest`.

  Three adversarial reviewers checked the fix.
  - **Exploit:** every bank-visible output (refusals, ids, packages, case refs) was identical
    whether or not another bank used the id. The holder-side gaps they found are fixed: a bare-id
    capture, a bare-id denial of service, and an unattributed refusal audit.
  - **Completeness:** nothing else still keys requests by id alone.
  - **Mutation:** every one of the 15 non-equivalent mutants of the new guards is killed. Three
    remaining mutants are provably equivalent: those guards are backed up by ids that already
    include the bank.

## Open issues (known, not fixed)

Fixed since the first version of this report: request ids were global across banks (major).
See "Per-bank request ids" above.

1. **Cross-request double counting (investigation).** One payout backing two credits that are
   asked about in separate RFCs gives `supported` twice. Within one run it is caught. The fix
   needs a scoped, budgeted gateway transaction listing.
2. **Settlement issuer on the passport path (investigation).** The gateway binds lookups to the
   payout's issuer. A settlement already held from another pinned issuer is not checked against
   the payout's `issuer_id`.
3. **Subject binding in packages is opt-in.** `PackageScope` has no `subject_ref`, so
   `verify_package` checks the subject and request only when callers pass `expected_subject` and
   `expected_request_id`. Bank-side callers must pass both.
4. **The withheld-value scan only matches strings.** Paraphrased item names, prices written in
   prose ("£180.00"), issuer display names and values under 4 characters can reach claim text.
   Scrubbing an extract can also over-redact.
5. **Holder imports can soften a contradiction.** A self-supplied payout with the same amount can
   turn `contradicted` into `unresolved`, though never into `supported`.
6. **Question classification uses keywords.** For example, "What did you use the funds for?" is
   classed as source of funds.
7. **DESIGN.md is behind the code** for several signatures. The "Differences from DESIGN.md"
   section of `CONTRACTS.md` is current, and the code wins.
8. **Fixture RFCs expire** at 2026-11-11T09:00Z (RFC A) and 2026-11-12T09:00Z (RFC B).
   - `load_fixture` defaults to the fixture clock (2026-11-07T12:00Z) and returns it as
     `fx["now"]`. Pass `now=fx["now"]` to later calls.
   - If the demo uses the wall clock after those dates, move the expiries in
     `alibi/fixtures/maya.py` and regenerate with `uv run --frozen python -m alibi.fixtures.maya`.
