## How it was checked

Six builders wrote disjoint modules in parallel against the committed foundation; an
integration pass ran the whole suite; two adversarial reviewers (injection and reference
laundering; control flow and verdict logic) wrote reproductions and confirmed 13 defects, all
fixed with regression tests. Examples now fixed: the Challenger could flip a reconciled,
settled claim to `contradicted` by citing any record in the material (now only an
explicit-field conflict counts); message records could reach `Claim.evidence_refs` through
`conflicting_refs`; the one-pass baseline appended model refs without the shareable check and
let short message sentences into the bank-facing statement; a stale Challenger proposal could
downgrade a verdict computed on material it never saw; `model_calls` undercounted failed
parses; Detective alert text was stored verbatim (now built in code from the kind and refs);
an empty Matcher signal crashed the run. One more fix after the live runs: the generic
"evidence withheld" gap text reaches the bank only when something was in fact withheld.

## Open issues (known, not fixed)

1. `alibi/api.py` still raises `NotImplementedError` for `mode="agents"` and `"single_call"`;
   the dispatch is `alibi/NEEDS.md` item 1. Callers import
   `alibi.agents.runner.run_investigation` and `alibi.baselines.one_pass.run_investigation`.
2. `lookup_payouts_covering` and `lookup_by_date` are served from the passport listing, not the
   mock merchant (`NEEDS.md` item 2). Argon chose `lookup_settlement` in every live run, so they
   are exercised in tests only.
3. Core policy cannot express category, merchant, per-target recipient or alert-preference
   rules; the parser returns them in the team shape and lists them under `core_reasons`
   (`NEEDS.md` item 4). The integration session should enforce those with
   `agents.execution.api.apply_policy` or hold the package.
4. Tokens of a call that failed the schema are reported as 0 (`NEEDS.md` item 5, needs `usage`
   on `SchemaValidationError` in `alibi/llm/client.py`).
5. The question classifier for fixture questions is the rules engine's keyword classifier
   (S1 open issue 7); team question ids (`q.source_of_funds` and so on) are used first when
   present.
6. Gemma's second opinion compares only the Matcher decision and the Detective's status and
   `confirms` refs; one of four live answers was not valid JSON. It never upgrades anything, so
   a flaky Gemma only makes Alibi more conservative.
7. Recordings replay by prompt hash, then by role order. A changed prompt replays by order, so
   a replayed trace after a prompt edit is labelled but may not correspond line by line.
