## How it was built

Understanding first: five parallel readers mapped the rules engine, package/approval/policy, store/ingest, templates/CSS and the contracts. The case adapter (`alibi/app/cases.py`) was written and proven on cases 1 and 2 before any route existed. One agent added the template hooks against a written variable spec while the Python was written; a skeptical reviewer re-rendered every page. Then four adversarial reviewers (security, correctness, spec, robustness) attacked the running app and 43 verifiers tried to refute each finding by running it. Confirmed and fixed, each with a regression test: inline-HTML XSS on the source and 404 pages; bank dispositions visible on the holder's audit page; no cross-site POST protection; the analyst credential staying in the URL; a rejected package's scope and claim counts in JSON and in the inbox; an excluded record's id leaking through an attachment summary built from the passport instead of the disclosed content; reruns dropping the holder's removals; the wrong "current" draft or approval on a fixed clock; a failed delivery shown as `sent`; invalidated claims shown as a complete investigation; a period package reconciled against a made-up target; expired requests still runnable and approvable; a sent request re-runnable into a second package; `restore` answering 500; the follow-up period error dumping a validation trace; default-shaped 400/404/405 bodies; `ALIBI_NOW` crashing on a date; the reset note deleting the shared master key. Refuted: the direct `alibi.core` imports (read-only display helpers; the brief names the core policy parser itself), and several items that described the committed code rather than the fixed worktree.

## Notes for the merge and the demo

- Start: `uv run --frozen python -m alibi.app` (port 8100). Holder: `http://127.0.0.1:8100/passport`. Bank A: `http://127.0.0.1:8100/bank/bank_a/inbox?token=demo-token-bank-a` (once; it redirects to the bare URL with a session cookie); Bank B: `...bank_b/inbox?token=demo-token-bank-b`. Case 2: `ALIBI_CASE=2`. Reset one case by deleting `data/alibi/app/case_<n>.db` and `case_<n>.state.json`; `master.key` beside them encrypts every case database there.
- An approval is valid for 15 minutes (`alibi.core.approval.DEFAULT_APPROVAL_TTL`). A presenter who approves and talks for longer gets `approval_expired` at dispatch; remove and restore an item (or rerun) for a fresh draft and approve again.
- The demo keystore (`data/alibi/keys`) gains two record-signing keys (`mock_marketplace`, `second_platform`) so data's issuers can sign; the registry file is rewritten with them, a superset of S1's four keys.
- Case adapter mapping (`alibi/app/cases.py` docstring): `sale`→`order`, `balance_release`→`payout` with status `released_to_balance` and the withdrawal reference from the message, `payout`→`settlement` with `effective_at = settled_at`, `purchase`→`receipt`, `notice`/`statement`→`message`. Two records, never two revisions.
- The analyst preview page is rendered from the app's own verified package view rather than `agents.eval.api.build_analyst_preview`, which projects gold facts without a signed package; the brief allowed it "where it fits".
- Attestation shows the two values the core verifier emits (`issuer_signature`, `package_signer`); `none` from the Trust row is never produced here.
