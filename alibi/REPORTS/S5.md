## Item 1: fixes

**1a llm.** Every role schema is closed (`additionalProperties: false` at every level, including
`next_action.args`); the validator rejects non-finite numbers and `parse_json` refuses `NaN` /
`Infinity`; every transport attempt spends one unit of both the process cap and the task budget

## Decisions and deviations

- **Bare request ids (S1 commits 8804ec3 and f6fba51 cherry-picked).** The S1 branch's second
  commit made every holder call without `audience=` raise `TypeError`. The app, the demo cases and
  teammates' acceptance tests (`agents/eval/test_redteam_core.py`,
  `agents/execution/test_dispatch_conformance.py`) call `run_investigation` and `build_review`
  with bare ids, so the merged rule keeps both behaviours: a bare id resolves while exactly one bank
  has used it; once several banks have, the public API raises `AmbiguousRequest` and `audience=`
  names the bank; the store resolves a bare id to the request received first, so a later bank never
  captures an earlier one's drafts (eval's `test_independent_banks_can_reuse_their_own_external_request_id`).
  Store key is `(issuer, request_id)` with `audience=` accepted as an alias; a schema-2 database is
  migrated on open rather than refused (restarts must keep history). `alibi/CONTRACTS.md` and
  `alibi/REPORTS/S1.md` say so.
- Subject binding lives in the signed `case_ref` (now a digest over audience, root request and
  subject) rather than a new `PackageScope` field, because eval's native verifier
  (`agents/eval/native_verify.py`) rejects any extra key in body or scope. Packages signed before
  this change carry the old `case_ref` and fail a subject-bound verification.
- `Claim.gap` is now a code; the app shows `gap_detail` (the sentence) and `gap_code` passes pinned
  codes through. The analyst package template still prints `PackageClaim.gap` (code) in one place
  (research-owned template; the sentence is appended to `rationale`).
